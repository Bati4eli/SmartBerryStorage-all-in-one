# AGENTS.md (workspace root)

Этот каталог объединяет **два независимых git-репозитория**:
- `MyCloud-Backend`
- `MyCloud-AndroidClient`

Документ задает правила работы AI-агента на уровне общей папки.

## 1. Приоритет И Непротиворечивость
1. Инструкции пользователя в текущей задаче.
2. Этот `AGENTS.md` (корень workspace).
3. Локальный `AGENTS.md` целевого репозитория:
   - `MyCloud-Backend/AGENTS.md`
   - `MyCloud-AndroidClient/AGENTS.md`

При конфликте правил агент обязан явно указать конфликт и запросить приоритет у пользователя.

## 2. Границы Репозиториев
- Всегда явно определять, какой репозиторий(и) затрагиваются задачей.
- Не смешивать изменения двух репозиториев в один набор действий без необходимости.
- Для каждого репозитория выполнять команды в его собственной директории.
- Не выполнять git-команды в корневой папке-агрегаторе (она не является единым репозиторием).

## 3. Git-Дисциплина
- `MyCloud-Backend` и `MyCloud-AndroidClient` считать отдельными зонами ответственности.
- Проверять статус отдельно в каждом репозитории (`git status` в каждой папке).
- Если изменения в обоих репозиториях нужны по задаче, фиксировать это явно в отчете:
  - что изменено в backend;
  - что изменено в android-клиенте;
  - почему изменения связаны.
- Не выполнять откат/сброс (`reset --hard`, `checkout --`) без явного разрешения пользователя.
- Не выполнять `stash`.
- Не делать commit автоматически по итогу задачи.
- Каждый новый файл добавлять в git сразу после его создания: выполнить `git add <path>` для этого файла до следующих правок.
- Если пользователь просит сделать commit, коммитить все файлы, а не только измененные агентом.

## 4. Контракты И Синхронизация
- Если меняется контракт взаимодействия (DTO, protobuf/gRPC, API-модели), проверить влияние на оба репозитория.
- При необходимости синхронно обновить backend и android-клиент.
- В итоговом отчете отдельным пунктом описать совместимость версий и что нужно обновить/пересобрать.
